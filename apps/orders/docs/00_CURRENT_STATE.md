## Known Limitations

- Buyer-message read state uses `sales_order_message_state` as the canonical
  Supabase store. Cloudflare KV remains a compatibility mirror during the
  post-cutover watch and can be removed after state parity is verified.
- Current minute-offset cron expressions approximate dependency order but do
  not prove upstream completion or per-order accounting.
- Marketplace discovery is not a complete lifecycle reconciliation contract;
  issue #265 demonstrated stale paid-state persistence despite green scheduled
  runs.
- `reconcile_end_to_end` currently re-invokes Mercari pull, Giga push,
  tracking pull, and marketplace close, so it is not read-only and must not be
  migrated unchanged.
- `close_rakuten_orders` is present in the active Worker schedule although its
  source comments and VPS timer still identify the RMS close contract as
  unverified. Production mutation history and contract authority require an
  immediate bounded audit before this capability is treated as approved.
- Repository scheduler/runtime descriptions are being reconciled; deployment
  intent alone is not evidence of live activation.
- Direct Cloudflare schedule API readback confirmed all 13 current main-Worker
  triggers and confirmed both historical reporting Worker names are absent.
  A future cutover still requires a fresh pre-change and post-change readback;
  the 16:03 snapshot does not authorize or prove an ownership transfer.
- VPS also runs an enabled `giga-mercari-pipeline.timer` owned by CatalogSync;
  it is a catalog/listing pipeline, not an OrderMgmt order workload. Its latest
  observed service exit was 2 and belongs to CatalogSync follow-up, not this
  strategy's scheduler ownership.
- The operation ledger intentionally does not reclaim `RESERVED`,
  `UNKNOWN_RESULT`, or `DEFINITIVE_FAILURE` by age. The branch now contains
  governed operator resolution tooling, but migration replay, permission
  readback, dry-run and bounded production canary evidence are still missing
  and block live activation of ledger-backed writers.
- The control-plane workload backlog is a bounded operator signal, not a full
  accounting proof; `truncated=true` requires an authoritative diagnostic.
  Target VPS ownership remains unproved until an approved ownership event,
  matching live lease/release evidence, Cloudflare phase step-down and
  post-cutover trigger/runtime readback all agree.
